# 微信餐饮小程序前端改版设计

## 目标

将现有餐饮小程序统一成“餐饮专业 + AI能力展示”的混合风格，用于真实点餐流程和简历项目展示。首页、购物车、订单等页面保持餐饮场景的清晰高效；AI推荐、智能点餐Agent、AI营养师页面突出智能能力，但不做成技术演示页。

## 设计方向

- 整体使用暖色餐饮主视觉：主色 `#DC2626`，辅助色 `#F87171`，行动按钮色 `#CA8A04`，浅暖背景 `#FEF2F2`，深色文本 `#450A0A`。
- AI功能使用克制的蓝紫色作为局部强调，只出现在 Agent、AI推荐、营养师的入口、标签和状态提示中。
- 页面采用移动端小程序常见的紧凑布局：搜索、分类、菜品列表、购物车结算栏优先，不做大面积营销型 hero。
- 卡片圆角控制在 8px 左右，按钮、输入框、底部结算栏保持统一高度、间距和视觉层级。
- 移除页面里的 emoji 图标，改为更正式的文字标识、线性图标占位或 CSS 形状，避免简历项目显得粗糙。

## 页面范围

- 首页点餐：统一搜索栏、店铺信息、分类胶囊、菜品卡片、加购按钮和底部购物车栏。
- AI推荐页：保留刷新推荐、加入购物车、跳转智能点餐Agent和AI营养师，强化“AI能力入口聚合页”的定位。
- 智能点餐Agent页：保留输入需求、生成方案、确认加入购物车；将开发者文案 `tool trace` 改成用户可理解的“决策过程”，展示“理解需求 / 筛选菜品 / 生成方案”。
- AI营养师页：统一表单、BMI结果卡、推荐菜品卡和加购按钮。
- 购物车页：统一确认订单、桌号、备注、菜品数量控制、提交订单、支付提示样式。
- 我的页：统一登录卡片、功能菜单、管理员入口样式，减少 emoji 带来的不专业感。

## 交互原则

- 所有菜品推荐和 Agent 方案只加入购物车，不直接支付，结算仍由购物车统一完成。
- 底部购物车栏在相关页面保持一致：左侧数量和金额，右侧“去结算”。
- 用户能看到 Agent 的决策过程，但默认用自然语言展示，不直接暴露 JSON 或代码。
- 空状态、加载失败、购物车为空等状态使用统一文案和按钮风格。

## 实现约束

- 保留现有业务逻辑、云函数调用、购物车存储和支付流程，不在本次 UI 改版中重写支付。
- 优先修改现有页面的 template/style，必要时提取少量公共样式，但避免大规模重构。
- 不引入新的前端框架；继续使用 uni-app / Vue / 小程序兼容写法。
- 不依赖远程字体，避免微信小程序加载和兼容问题。

## 验证

- 运行已有前端相关 Node 测试，重点覆盖推荐、营养师、智能点餐和购物车行为。
- 本地 `npm run build:mp-weixin` 仍可能因为缺少 `uni` CLI 失败，最终小程序运行由 HBuilderX 验证。
- 检查页面中不再出现 `tool trace`、明显 JSON 输出和主要 emoji 图标。
